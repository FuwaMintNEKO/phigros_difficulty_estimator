## 1. 模型基线选择建议

**结论：以生产模型 10.1（3类）为唯一优化基线，v14 stable 降级为"社区体感对照"工具。**

理由：
1. 官谱歌曲分组 CV MAE 0.5264 < stable 0.5399（-0.0135），且 IN/AT 合并、低段加权、尾杀、eff_* 等全部经诚实 CV 验证有效（见 30.7/30.11.7/30.11.6c）。
2. stable 唯一的优势是"对自制谱预测偏低 0.3~0.5，更贴近社区标注体感"（30.13.2）——但这本质是它 CV 更差的表现，且社区标注与官谱标尺的系统性偏差已由 30.10 双向互证量化（高端偏低 0.4~0.8）。**贴近社区体感不应通过选更差的模型实现，而应通过 P0-1 的预测时校准实现**。
3. stable 训练/推理的 boost 对齐、p95/p99 语义一致性均不如生产模型（30.9.7 遗留问题在 stable 上更严重）。

使用建议：保留 stable 文件不删除，新增 `tools/compare_prod_vs_stable.py`（见 P3-3）做对照展示；一切后续优化只动生产模型。

## 3. P0 立即落地（证据充分、改动小）

### P0-1 预测时校准落地（最高 ROI，30.12.5 实验B 已验证）

**背景**：纯官谱 3 类模型对社区谱（上架/未上架）在 14-16.5 段系统性高估 +0.19~+0.28，根因是社区定数口径与官谱口径的差异 + 自制谱特征分布 domain gap。训练时校准已证明无效（30.12.5 实验A：混合训练污染官谱学习），**预测时校准是唯一验证有效的手段**。

**落地设计**（app.py `predict_one_chart` 的 `is_custom` 分支末尾）：

```python
# 预测后校准（仅自制谱；官谱不做任何调整）
_CALIB = {  # 段键 = (lo, hi]，校准量
    'ranked':   [(13, 14, 0.18), (14, 15, 0.28), (15, 16, 0.21), (16, 17, 0.07), (17, 99, 0.0)],
    'unranked': [(16, 17, 0.17), (17, 18, 0.05), (18, 99, 0.37)],
}
def apply_predict_calib(pred, is_custom, source='ranked'):
    if not is_custom: return pred
    for lo, hi, adj in _CALIB.get(source, []):
        if lo < pred <= hi:
            return pred - adj
    return pred
```

**待用户确认的两点**（30.13.4 原文）：
1. 按来源选校准表：app.py 无法自动区分上架/未上架，建议默认 ranked（用户测试集以上架为主），unranked 做成可选参数；或两表合并为折中表（14-16.5 用 ranked、≥17 用 unranked 减半）。
2. ≥17 段样本不足（上架 39 / 未上架 21）：建议 ≥17 校准量 ×0.5 平滑，避免过校正。

**验证方式**：落地后跑 `tools/_tmp_calib_predict.py` 同口径对比；test_charts 抽查 silly-willy-nilly（17.89→~17.8）、恋ひ恋ふ縁（16.98→~16.8）。

### P0-2 2xBPM/时间压缩谱检测（30.12.4 遗留）

**背景**：ギザバ怪文書(18.3)_2xBPM 预测 21.09（+2.8），根因是 BPM 翻倍压缩导致 nps/密度特征在时间域失真（78s 塞 2666 notes，nps 33.85）。

**设计**：在 predict_one_chart 前增加轻量检测，命中时在返回结果中加警告字段（不改预测值，避免误伤正常高速谱）：
- 检测 BPMList 是否存在整体 ×2 模式（相邻段 bpm 比值 ≈2 且时长极短），或
- 谱面时长 < 音乐时长预期且 nps 超 P99 的 2 倍（nps > ~20 时提示"疑似时间压缩谱，预测可能偏高"）。
- 前端显示黄色警告条；文档标注"2xBPM 版谱面请用倍速 0.5x 重新预测"（app.py 已有 apply_speed_multiplier，0.5x 后 nps 回落到正常域）。

### P0-3 project_memory.md 沉淀

把 docs/估算偏高问题审计与修复.md 的 30.13 结论 + 本方案的关键决策（模型基线、校准落地状态、未决事项清单）浓缩为项目根目录 `project_memory.md`，作为跨会话的第一入口。同时把 `docs/README.md`（停留在 v8.1）更新到 10.1 现状。

## 4. P1 模型/特征层（有实验依据，需诚实 CV 验证）

### P1-1 尾杀窗口细化（30.11.5 关键发现 2）

**证据**：QZKago 尾杀 20s 被正确识别（tail_core_share=0.27 最高），但 DF"最后 5 秒"被 15% 窗口稀释（tail_peak_ratio 仅 0.90 不突出）。DF/QZKago 恰恰是社区公认"尾杀集中度"差异最大的两张 17 谱。

**方案**：compute_tail_features 增加两档窗口——末段 5%（tail_peak_5pct）与固定末 3 秒（tail_peak_last3s），与现有 15% 窗口特征并存（不替换，防止 EZ 段噪声回归，30.5 教训）。分组 CV 验证是否再降 IN 段 MAE（当前 IN 0.3591 已是最好段，边际空间小，但 HD 段有空间）。

### P1-2 chord_size_entropy 计算逻辑排查（30.11.5 关键发现 3）

**证据**：该特征几乎全为 0 或负值（-0.00~0.93），未刻画和弦大小分布的信息熵。它是 boost 特征（co=0.034）且 30.11.6a 显示它在 GB 中贡献极小——很可能计算 bug 导致信息量丢失。

**方案**：审计 feature_extractor 中和弦熵的实现（熵计算是否对 0 概率项处理错误/和弦大小聚合窗口错误）；修复后跑全 982 官谱统计分布是否恢复"正且随定数单调"；若修复后与现有 chord_complexity 共线则二选一进 boost。

### P1-3 boost 特征 p95/p99 缺失补齐（30.9.7 遗留）

**证据**：chord_size_entropy、weighted_mf_score_per_sec、type_switch_per_sec、multi_finger_3plus_events 4 个 boost 特征在训练时未计算 p95/p99（P95.get→0），boost 阈值退化为 baseline*0.5。当前训练/推理自洽，但偏离"按 p95 触发"的原始语义。

**方案**：重训脚本在计算 P95/P99 时对全部 MANUAL_FLAT 特征（而不只是 gb_feature_names）计算；重训后对比 CV（预期持平或微升，因为阈值语义更准）；若 CV 变差则记录结论保持现状。

### P1-4 eff_* 有效单指密度的增益量化（30.11.6c 方向，已实现未验证）

**背景**：生产模型已含 eff_peak_tps_1s（co=0.20）/eff_avg_tps_1s（co=0.08），设计目标是区分"4 押全押顺手"（volcanic core_peak 28）与"单指连打底力"（D321 core_peak 27）。但 30.13.1 只报告了整体 CV 提升，未单独验证这两个特征的去留。

**方案**：--noeff 开关重训对比（同 train_final_v10.py 的 --variant 模式），若 CV 无提升则考虑从 boost 移除（减少过拟合面）；同时用 volcanic/D321/ReEnd 案例确认 eff_* 确实修正了"多指全押虚高"。

### P1-5 "难度形状"特征（P2 盲区中最有希望的一个）

**证据链**：30.11.3 盲区 #1（可馅蜜/容错无特征）→ BANGING STRIKE（特征最强却被评"最水"）、30.9.6（ALL☆NIGHTER! 协调型可馅蜜高估）、30.9.5（前段五段低密度白送 + 难点集中尾杀）。这些谱的共同点：**难度集中在后段、前段可馅蜜**——即"难度形状"而非"难度总量"。

**方案**：构造两个静态可计算特征（不依赖社区标签）：
- front_rest_ratio：前 50% 时长内 rest 占比（前段白送度）
- tail_concentration：后 15% 段密度 / 前 85% 段密度（难点集中度，与 P1-1 的 5% 窗口互补）
进入 GB 特征池（不强制进 boost），分组 CV 验证。风险提示：30.9.3 已证明官谱上"协同类交互特征"全部无效，若 CV 无改善则接受"体感衰减因素无法从官谱学习"的结论（30.9.6 根本结论），转 P2-2 用社区标尺工具化。

## 5. P2 数据与标尺层

### P2-1 输出离散化 0.1 + 置信区间

- 官方定数是 0.1 精度离散值（30.12 末节：鸽游内部确认精确到 0.1）；Rhythematics 反推方法学也依赖 0.1 档。
- 建议：前端展示 round(pred, 1)；API 增加 prediction_rounded 字段。
- 置信区间：用歌曲分组 CV 的 per-段 MAE（EZ 0.638/HD 0.632/IN 0.359/AT 0.416）作为区间展示（±1 MAE），比没有区间强。

### P2-2 社区定数标尺工具化（30.10 双向互证）

结论已存在：社区标尺中段（14-15）≈ 官方，高端（15→17.6）偏低 0.4~0.8，AT 段尤甚（-0.617）。建议做成 tools/scale_calib_report.py 定期输出（每次拉新 phira 数据后跑），不改变模型，只作为"社区定数 ↔ 官方定数"的转换参考，供用户解读自制谱社区标注时使用。

### P2-3 定数漂移快照管理

3.11.0 一次调整约 60 首（±0.1~0.4）。建议：
- difficulty.tsv 增加版本快照目录（data/info/difficulty_3.19.tsv 等），训练脚本支持 --tsv 参数；
- 模型卡记录训练时 tsv 的 git/文件哈希，防止未来"换 tsv 重训但忘了记录"。

## 7. 风险与边界（已由历史实验证明的"不可行域"，不要重复投入）

1. **混合训练（官谱+社区谱）**：已否决（30.12.3/30.12.5 实验A：官谱 MAE 0.5528>0.5264，上架 +0.395 未被纠正）。除非未来社区定数质量大幅提升，否则不再尝试。
2. **训练时标签校准**：已否决（30.12.5：过校正 -0.373）。
3. **协同/位移/底力交互特征**：8+8 个交互特征全部无效（30.9.3/30.9.3b），GB 树已隐式学到，不重复造轮子。
4. **isotonic 校准器**：诚实 CV 0.572>0.546，过拟合假象，否决（10.4/30.1）。
5. **Huber/log1p 损失**：无增益（10.3/30.2）。
6. **2xBPM 类变速谱**：模型与社区都处理不好（11.12-6），预测偏差是系统性盲区，只做检测提示不做修正。
7. **≥17.8 外推**：官谱标度上限 17.6，>17.8 的预测无官方参照，只能靠 boost 指数外推（30.12.4 中 18-21 段预测仅供参考）。
