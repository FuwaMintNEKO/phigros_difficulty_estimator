### 社区候选谱 (验证"休息段多高潮段难")
- **Cheerio AT (58496, 社区17.1, 预测16.74)**: 156s
  - 0-16s: nps 1-4.4 (开头平缓) | 40-64s: nps 6.6-7.1, **多押18-40** (高潮1)

  - ✅ 用户描述完全验证: 休息段稀释dens均值, 高潮段+尾杀硬核
- **NECROPTOSIS (45520, 社区17.6, 预测15.93)**: **354s超长耐力谱**
  - 56-72s: nps 5.6-7.4, 多押35-43 | 112-136s: 多押47-50 | **208-216s: nps 6.75, 多押68-74**
  - 152-168s空窗 + 224-264s长空窗(drag) — 休息段极多
- **Coming True (45563, 社区16.2, 预测14.96)**: 182s
  - nps峰值仅4.8, 但**多押持续33-47** (48-64s, 128-176s)
- **あいしていたのに (40178, 社区17.2, 预测13.78)**: 206s **慢速多押海**
  - nps仅2-3, 但**每窗口和弦26-81** (24s:81, 64s:73, 152s:73)
  - 多指协调难度极高, 击打频率低 → dens极低(4.0) → 被重压档误伤

### ★ 核心发现: 三种"dens均值误伤"形态
1. **耐力型多指** (NECROPTOSIS): 超长+多空窗, 高潮多押密集
2. **持续多押型** (Coming True): nps不高但多押密度高
3. **慢速多押海** (あいしていたのに): 击打慢但和弦海
共同点: **多押事件密度(每窗口和弦数)是核心难点, 被nps/dens均值稀释**
→ 现有特征 weighted_mf_score_per_sec / multi_finger_3plus_events 是聚合值, 无法区分"多押分布"形态
→ 候选新特征: chord_events_per_sec_peak (多押事件峰值密度) / heavy_chord_window_ratio (多押密集窗口占比)

### ★ 审计核心发现
1. **低密度+高多押 = 模型OOD域**: 官谱16+多押谱全是高速型(hard 35-67%), 社区慢速多押海谱(16-17段)无官谱支撑 → 低估0.6-3.4
2. **mf档位误伤**: dens<9.5 → mf×0.50 重压, 误伤"间歇多押"型(Cheerio dens 8.4 但 chHv 80%)
3. **官谱标尺本身偏差**(玩家感知): 321 AT官方17.3玩家15.8(虚高1.5) / BTTB官方14.5玩家15.3(虚低0.8) / DF官方17.4玩家认为虚高(前半简单) — 预测器忠实继承
4. **密度外维度**: BTTB案例显示变速/读谱/长条干扰维度可能缺失或权重不足
5. **多押事件密度是玩家核心难点**: 8秒窗口和弦数20+ = 玩家眼中"多押密集段", 现有特征(聚合wmf/mf3)无法区分"间歇型vs全程型"多押分布
