# v11.1 定轨段特征改良（2026-08，本会话续）

## 背景

用户指出 test_charts 中 Chart_SP 含大量 4k/5k/6k 定轨配置（定轨音游玩法：固定槽位密集击打、多指分工、双指无解），应升到 17+。同时澄清：**多押只算 tap+hold**（flick/drag 同押不算多押，回滚了此前 flick 计入的实验）。

## 诊断过程

1. **概念澄清**：4k/5k/6k ≠ 同时押数，而是"定轨键盘段"（positionX 固定槽位上的密集击打，类似 osu!mania 玩法）。
2. **段落分析**：Chart_SP 的 20-60s 是 4k 段（槽位 -6,-2,2,6）、70-120s 是 5k 段、120-130s 是 6k 段，每 10s 85-160 音符（密集）。
3. **特征缺失确认**：现有特征体系（多押/楼梯/位置熵）无法刻画"定轨槽位数 × 时长"，模型预测 16.79（<17）。

## 实现

### 新特征（feature_extractor.py `compute_track_segments_features`）

- 2.5s 滑动窗口，窗口音符 >=6 才统计（密集段）
- 窗口内 positionX 聚类（间距 >=1.5 分隔为槽位），槽内音符 >=4 计为主导槽
- 主导槽数 k = 该窗口的"定轨数"（4k 段 k=4, 5k 段 k=5, 6k 段 k=6）
- 输出 6 个特征：tracks_4plus_sec / 5plus / 6plus / max_k / avg_k / active_sec

### 官谱分布验证

| 特征 | corr(定数) | 官谱 max | Chart_SP |
|---|---|---|---|
| tracks_active_sec | **+0.857** | 167.5s | 112.5s |
| tracks_max_k | **+0.788** | 8 | 7 |
| tracks_avg_k | **+0.787** | 3.4 | **4.02（超官谱）** |
| tracks_4plus_sec | +0.603 | 67.5s | **82.5s（超官谱）** |
| tracks_5plus_sec | +0.388 | 27.5s | 27.5s（并列最高） |
| tracks_6plus_sec | +0.155 | 10s | **7.5s（自制谱唯一）** |

### 推理层加成（app.py, 仅自制谱, 校准前）

```python
# 占比归一化（防长谱误伤）: r = 各轨段时长 / 活跃总时长
p_final += 0.15 * min(r4, 0.8) + 0.55 * min(r5, 0.4) + 1.0 * min(r6, 0.15)
```

- 5k/6k 段是"双指无解"的核心（4k 段官谱常见, 模型已学; 5+/6+ 稀缺）
- 上架谱 589 张平均加成 +0.038，97% 谱 <0.15，无系统性影响

# v11.2 特征层面改良报告（2026-08）

## 背景与目标

用户要求：去掉硬编码 cap、不加协同、在 v11.1 基础上找**特征层面**的不平衡问题，以全部上架（589）+ 未上架（957）谱为评估基准，优雅平衡定数。并行研究（AgentTeams 3 任务）结论汇总后实施。

## 研究结论（t1/t2/t3 + 船长分析）

1. **t1 偏差定位**：上架谱 14-15 +0.12、15-16 +0.09、16-17 +0.01、≥17 -0.31；高估 Top20 中 **18/20 是双指谱**（密度/多押/读谱量超官谱 P90），双指 eff×1.5 抬升放大堆料高估；低估 = 特征不足谱（低密度被社区高定、纯 hold、长 drag）。
2. **t2 密度虚高根源**：above_avg_density_mean 用原始窗口 TPS（4k 全押计 4 音符）→ 方案 B：改按**有效击打数**（同押去冗余）。官谱 corr 保持（P 0.904/S 0.948）、上架偏差 +0.040→-0.006、高难段降 8-40%。
3. **t3 未上架域偏移**：mf3 P90=113 是官谱 2.7 倍、多指谱占 44.7%、>18 占 5.2%——OOD 堆料是主要形态。
4. **船长发现**：weighted_mf_score_per_sec 中双押（2指）占 97%+（Breakcore 99.7%），"双押宽押"被误算为"多指协调"；silly 是纯多指谱（mf3 低但快速大跨度击打）——mf3 分档不能完全代表多指需求。
